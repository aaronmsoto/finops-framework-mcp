# 2026-08-02 — T-060..T-063: six-page usage guide (docs/guide/)

Owner directive: grow the single ESR walkthrough artifact into a full
documentation guide, planned by Fable and implemented via Opus/Sonnet
subagents, hosted GitHub-Pages-style, looping until done.

## What shipped

`docs/guide/` — six self-contained HTML pages, GitHub-Pages-ready:
index (intro + getting started), framework-server, focus-server, and three
worked examples (showback, esr, forecasting). Spec:
`.agents/specs/usage-guide-v1.md`.

## How it was built

One Workflow, six parallel page builders + an adversarial consistency
checker:

- **opus** built the narrative-heavy pages (index, showback, forecasting)
- **sonnet** built the reference pages and the ESR restyle
- **opus** checker verified nav/links/footers and re-probed 8 sampled
  factual claims across the data-heavy pages

Binding rule from the spec: every fact, count, quote, and transcript comes
from a live probe (`evals/framework/mcp-call.mjs`) or committed data.
**103 probes** recorded across the six pages (showback 37, forecasting 24,
index 15, focus-server 12, framework-server 10, esr 5).

Checker returned ok:true with **zero fact mismatches**, but flagged chrome
defects outside its fix mandate: the builders had produced TWO chrome
variants (different header/nav/footer markup, classes, and DOM position),
four pages had duplicate `<h1>`s, the forecasting page had the generic
index `<title>`, and index.html presented a transcript as captured while
its JSON whitespace had been hand-tidied.

A follow-up opus normalization pass unified all six: identical six-link nav
with aria-current, one h1 per page, footer after `</main>` with identical
CC BY 4.0 attribution + UNOFFICIAL legend, consistent doctype/viewport
skeleton, overflow guards, and the transcript re-pasted from a fresh probe
so the "captured" claim is literally true. Content diffed against a
pre-change backup: unchanged everywhere except that whitespace hunk.

Supervisor re-verified independently (not trusting the agent's report):
h1 count, nav order/labels/aria-current, footer-after-main, title pattern,
overflow guard, zero remote assets, plus md5 equality of the nav and footer
blocks across all six. All pass.

## Decisions recorded

- `docs/guide/` + GitHub Pages over a GitHub wiki (wiki = separate remote,
  no PR review, no gates). Consequence: the `designs` gate warns on all six
  pages ("HTML outside docs/designs/"); accepted as intentional —
  docs/designs is for design review, docs/guide is the published site.
- Guide content rule: live probes only; synthesized advice must be visibly
  labelled (the forecasting 90-day plan is boxed as the guide's own).
