# T-038 — Static demo web app for the combined walkthrough

Task: T-038 (`.agents/specs/focus-mcp-v1.md`, "Packaging / worker / demo").
Loop-build session, single task. Last v1 build task in the
T-027..T-038 batch.

## What I did

- `demo/` — a plain static site, no build step, no bundler:
  - `demo/config.js` — the one endpoint-config object (`CONFIG`:
    `workerBaseUrl` default + the two route suffixes), plus `endpointUrl()`.
  - `demo/requests.js` — pure JSON-RPC `tools/call` request-body builders
    (no fetch, no DOM) for the walkthrough's five static steps
    (`list_capabilities` → `get_capability` → `get_kpi_mapping`×2 →
    `compare_versions`), plus `calculateKpiRequest()` for the dynamic sixth
    step. Mirrors `evals/focus/combined-scenario.xml` steps 1-5 exactly —
    that file's header already says it "doubles as the demo app's (T-038)
    source script."
  - `demo/requests.d.ts` — hand-written ambient types for `requests.js`
    (TS resolves a sibling `.d.ts` for a same-named `.js` without needing
    `allowJs`), so the Node test importing it gets real types without
    pulling `demo/` into the tsconfig `include` (`demo/` stays outside
    `src`/`tests`, untouched by `format`/`lint`/`typecheck` gate scopes,
    which are `src tests`-scoped — confirmed by reading `agentic.config.json`
    and `tsconfig.json` before writing anything).
  - `demo/client.js` — thin `fetch()` JSON-RPC wrapper + `tools/call`
    error-unwrapping (`unwrapToolResult`).
  - `demo/app.js` — drives the walkthrough in the browser: runs the five
    static steps against the configured worker, then reads step 2's
    `sections.featured_kpis` (NOT hardcoded) to build one `calculate_kpi`
    call per featured KPI — so the demo genuinely follows capability → KPIs
    → columns → calculate, not a canned list.
  - `demo/index.html` — single page: worker-URL field (prefilled from
    `CONFIG`), "Run walkthrough" button, a log area that renders each
    step's title/goal/request/response as it completes, CC BY 4.0 +
    unofficial-mapping footer (mirrors `NOTICE.md`).
- `src/workers/demo-requests.test.ts` — imports `demo/requests.js` directly
  and drives the exact same request bodies through
  `createFetchHandler` (T-037, `src/workers/app.ts`) with the real
  `data/framework`/`data/focus` fixtures (same pattern as
  `src/workers/app.test.ts`). Asserts: capability lookup finds
  `rate-optimization`; the 4 featured KPIs match the eval doc's set;
  `get_kpi_mapping` for both 1.0 and 1.2 returns those same 4 KPI slugs,
  `official: false`; `compare_versions("CommitmentDiscountQuantity")` is
  `"added"`; each `calculate_kpi` value matches the combined-scenario eval's
  fixture numbers exactly (ESR 26.552972346576816%, utilization 0%, waste
  100%, consumption-vs-commitment 0). All values matched on the first run —
  no formula/mapping drift since the eval doc was written.
- `docs/deploy-demo.md` — owner checklist: point `demo/config.js` at the
  deployed Worker, add the demo's deployed origin to the Worker's
  `ALLOWED_ORIGINS` (`docs/deploy-worker.md` step 2), `npx wrangler pages
  deploy demo --project-name=...`, smoke test, rollback. No automation in
  this repo deploys anything (human approval point, same as the Worker).

## Result

- `./scripts/agentic gates --tier all`: format/lint/typecheck/test (357
  passed)/coverage/designs/integrity/memory/build all pass. (One pre-
  existing integrity WARN about mixing implementation with tests/policy in
  the diff vs `origin/main` — informational, not a failure; unrelated to
  this task's own changes, which are additive-only.)
- Observed behavior (real HTTP, not just direct handler calls): wrote a
  throwaway Node script (scratchpad, not committed) that starts a real
  `http.createServer` adapting Node's `IncomingMessage`/`ServerResponse` to
  the Web `Request`/`Response` the fetch handler expects, backed by the
  same `createFetchHandler` + real fixtures, then ran `demo/client.js`'s
  actual `fetch()`-based `sendRpc()` against it end-to-end using
  `demo/requests.js`'s builders and `demo/app.js`'s exact flow (static
  steps, then dynamic `calculate_kpi` per discovered featured KPI). All six
  steps returned 200/non-error, and the four calculated values matched the
  eval doc exactly. This is the closest available substitute for opening
  the page in a browser in this headless environment (no browser tool
  here) — it exercises the identical `fetch()` call path `demo/app.js`
  uses, over a real socket, against the real worker handler.
