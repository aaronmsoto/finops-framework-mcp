## T-083 — bump the MCP SDK to clear transitive advisories — 2026-08-15T00:00:00Z

- did: Caught during the npm publish pre-flight, not planned work. Running
  `npm audit` on the production tree before the first `npm publish` surfaced
  2 high + 2 moderate advisories, **all transitive through
  `@modelcontextprotocol/sdk@1.29.0`** — which is a production dependency of
  both packages, so every consumer of `npm install finops-framework-mcp`
  would have inherited them on day one. Owner chose to fix before publishing
  rather than ship 0.1.0 dirty and patch in 0.1.1.
  - Verified the fix existed before proposing it: installed
    `@modelcontextprotocol/sdk@1.30.0` into a throwaway directory outside the
    repo and confirmed it resolves `hono` 4.13.2 and `ip-address` 10.5.0 with
    `found 0 vulnerabilities`.
  - Bumped `^1.29.0` → `^1.30.0` in **both** `package.json` files — the FOCUS
    package declares its own `dependencies` block rather than inheriting from
    the root, so bumping only the root would have shipped a mismatched
    manifest for `finops-focus-mcp`.
  - **`npm install` alone was not enough**, and this is the non-obvious part:
    it updated the SDK and rewrote its dependency ranges in the lockfile
    (`@hono/node-server` widened to `^1.19.9 || ^2.0.5`) but left the already-
    resolved transitive versions pinned where they were, so `npm audit` still
    reported all 4. npm minimizes churn and will not move a transitive
    dependency that still satisfies its range. `npm update hono
    @hono/node-server ip-address express-rate-limit` was needed to actually
    take the fixed versions.
  - Two more advisories came out from behind that one. `fast-uri` (via `ajv`,
    3.1.4, host confusion via backslash authority introducer) — `ajv`'s range
    is `^3.0.1` and 3.1.5 is published, so `npm update fast-uri` cleared it
    without touching `ajv`. Then four **dev-only** ones — `brace-expansion`
    (eslint), `nanoid`/`postcss` (vitest→vite), `undici` (cheerio). Those
    never reach a consumer's install, so they were not blocking, but they
    cleared under plain `npm update` with no major-version jumps, so they
    were taken too.
  - Total lockfile churn: 35 changed line-pairs, all version/integrity/
    resolved-URL fields. No packages added, removed, or restructured.
- result: `npm audit --omit=dev` → **`found 0 vulnerabilities`** (the
  criterion that matters for the published tarballs); `npm audit` across the
  whole tree, dev included → **`found 0 vulnerabilities`**.
  `./scripts/agentic gates --tier all` **PASS** (format, lint, typecheck,
  test, designs, integrity, memory, build).
  - **Both servers exercised live under the new SDK**, not just compiled —
    an SDK bump touches the protocol layer, so a green build proves little.
    Framework stdio `tools/list`: 11 tools, `get_actions` absent (T-082's
    gating still holds). FOCUS stdio `tools/list`: all 9 tools present.
    Real `tools/call get_capability {capability: forecasting}` returns
    `title: Forecasting` with `source_url:
    https://www.finops.org/framework/capabilities/forecasting/`; FOCUS
    `list_versions` returns `['1.0', '1.2']`. Protocol round-trips, content
    lookup, and structured output all intact.
- implementer notes: worth remembering that `npm install <pkg>@<range>` does
  not refresh that package's own already-locked transitive tree — the audit
  looked unchanged after the bump and it would have been easy to conclude the
  SDK bump "didn't help" and abandon it. `npm ls <transitive>` before and
  after is the check that tells you what actually moved.
  The four dev-only advisories were fixed opportunistically because they were
  free; they are not part of the acceptance criteria and a future audit
  finding them again is not a regression of this task.
