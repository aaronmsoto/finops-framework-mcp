## T-007: derive step — all JSON regenerated from markdown, offline — 2026-07-23T01:40:00Z

- Did: implemented spec §3 (`.agents/specs/v1-official-only.md`) in full.
  - New `src/crawlers/framework/markdown/derive.ts`: a closed-dialect parser
    (front-matter, `#{1,6} ` headings tracked fence-aware, `- ` lists with
    2-space nesting, fenced code) that is the exact inverse of `compose.ts`.
    Per-doc derivers: `deriveCapabilityDoc` (→ `Capability` + `Action[]`,
    including reconstructing ordinal/parent_ordinal by flattening the first
    bullet list found per maturity level — mirrors the "first ul/ol, flatten
    descendants" rule in `parse/capability.ts` exactly, including an
    inline-markdown stripper since `maturity_raw` preserves `**bold**`/links
    that the original plain-text `Action.text` never had), `derivePersonaDoc`,
    `deriveKpiDoc`, `derivePrinciplesDoc`, `derivePhasesDoc`, `deriveDomainsDoc`,
    `deriveMaturityModelDoc`, `deriveTechnologyCategoriesDoc`,
    `deriveScopesDoc`. Directory-level `deriveFromDocs(docs: Map<path,text>)`
    (pure) and `deriveArtifactPayload(markdownDir)` (reads the directory,
    zero network/cache — no `CachedFetcher` import anywhere in this file).
  - `cli.ts`: extracted `assessArtifact` (completeness assertions + injection
    scan + count checks, shared) and `validateSchemas` (ajv, shared) out of
    the old inline `refresh` body. `refresh` now: fetch → parse → compose
    markdown (unchanged) → `deriveFromDocs` on the composed markdown (still
    in memory) → `assessArtifact`/`validateSchemas` against the DERIVED
    entities → emit. JSON is no longer taken from the HTML-parsed variables
    directly — they only feed the composer now. New `derive` subcommand runs
    the same `deriveArtifactPayload` → `assessArtifact` → `validateSchemas` →
    `emitArtifact` path against `<artifactDir>/content/markdown/` on disk,
    reusing the previous manifest's `source_urls` (no network to rediscover
    them). `main()` dispatches `refresh`/`derive`.
  - Design decisions (see decisions.md): (1) KPI reconstruction reads
    `kpis/<slug>.md` directly rather than re-joining Featured-KPI modal
    blocks from every capability doc, since `composeKpiMd` already fully
    materializes formula/data_sources/related/featured_on into that file. (2)
    Entity arrays are sorted by the entity's own `slug` post-derivation, not
    by markdown filename — a filename sort silently misorders whenever one
    slug is a prefix of another (found via real-data testing, see below).
  - **Real bug found and fixed during verification** (not itemized in the
    original spec, but required for "refresh then derive = zero diff"):
    `executive-strategy-alignment` and `usage-optimization` have no bolded
    summary paragraph on their pages — `cli.ts` was silently backfilling
    `cap.summary` from the WordPress API excerpt, but only onto the
    `Capability` record, never onto `page.summary`. Since T-006 composed
    markdown from `page` (pre-fallback), the Summary section was silently
    *absent* from those two capabilities' markdown — a real content loss
    once derive became authoritative (the API excerpt isn't crawled into
    markdown at all). Fixed by mirroring `page.summary = cap.summary` right
    where the fallback is applied, so the composed doc — and therefore
    derive's reconstruction — carries it. Root-caused via a live refresh
    diff (`content/capabilities.json` showing `summary: ""` for those two)
    rather than by inspection; the 5 unit-test fixtures all happen to have
    real summaries so this never surfaced there.
  - Tests (`derive.test.ts`, 21 cases): `derive(compose(parse(fixture)))`
    deep-equals `buildCapability(...)` + `page.actions` for all 5 capability
    fixtures (definition_md, headline_groups, maturity_raw,
    functional_activities, kpi_bullets, example_kpis, inputs_outputs_md,
    featured_kpi_ids, actions incl. ordinal/parent_ordinal — every field);
    a dedicated allocation ordinal/parent_ordinal test per spec wording;
    section-doc round-trips (persona, kpi with/without formula, principles,
    phases, domains, technology-categories, maturity-model with/without
    sample goals, scopes) each composing then deriving inline fixtures.
