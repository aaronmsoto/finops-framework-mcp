What it covers

The FinOps Framework and FOCUS describe how to manage technology spend and what the billing data looks like. This server adds the AI-specific layer: what drives token cost, how consumption grows with usage and autonomy, and which levers bring it down. The Seven-Layer Stack

The Foundation's organising model: the lower three layers set what a token costs, the middle three move a workload between Big-T classes, and the top layer sets the demand they all serve. list_layers returns the published summary table verbatim:

LayerMoves the multiplier?Key metricPrimary levers
L0 EnergyNo, sets the price and supply of powerEnergy per token, PUESite by delivered power price and capacity; contract supply; shift deferrable work in time
L1 Physical infrastructureNo, sets cost per tokenDollars per token, performance per wattMatch accelerator class to workload; adopt newer generations; place by region
L2 Infrastructure managementNo, sets effective cost per tokenUtilization, idle hoursBatch the troughs; autoscale; pool and share GPUs
L3 Inference stackYes, toward T(1) and T(log n)Cache hit rate, time to first token, throughputRight engine; prefix, KV, and semantic cache; disaggregation
L4 Model management and selectionYes, T(n·k) toward T(n)Cost per task, quality per dollarRight-size the model; quantize; configure the runtime; adapt
L5 AI access and controlYes, bounds T(n·k·a) and T(∞)Per-route cost, fan-out and retriesComplexity routing; budgets; agent caps
L6 Demand and entry pointsYes, sets the class a workload requiresRequest frequency, context volumeSet requirements per use case; trim and reuse context

Big-T notation is the companion idea: T(n · k · a) = requests × model calls per request × agent depth, with a six-class ladder from T(1) (cached, constant) through T(n) (linear, the healthy default) to T(∞) (unbounded). The “Moves the multiplier?” column says which classes each layer's levers move.

Worked demo: model routing and AI gateways

Routing is where much of the current AI-cost conversation sits. The chain an agent walks: a definition, the layer that owns routing, its levers, then the evidence across every source.

1

Define it quoted

“Model routing: Automatically sending each request to the most appropriate, often cheapest adequate, model.”

Source status: Tokenomics Draft Definition v0.5.2 (September 1 2026) · “What Is AI Tokenomics?”

tokenomics · define_term {term: "model routing"}

2

Find the layer that owns it: L5 AI access and control

L5 is the gateway layer. Its published description:

“AI access and control is the governed entry point in front of every model: admission and authentication, which model or deployment serves each request, caching at the gateway, budgets and quotas, fallbacks, the guardrails that bound agent fan-out and retries, and the attribution metadata captured from L6 and propagated with each request. It is the only layer that can decide whether a request needs no model at all, and the only one that can stop a workload consuming without limit.”

Its five published components separate the pieces that products often bundle together:

ComponentCovers
Access & AdmissionGoverned AI entry points, authentication & authorization, traffic blocking & kill switches
Proxy (Pass-Through)Transparent pass-through, rate limits, bounded retries, timeouts, fallbacks across providers, unified API surface
Router (Selection)Intent and complexity detection, model and provider selection, routing by data classification, cache, rules & no-model routes
Policy & GuardrailsPre-flight guardrails & compliance, response validation, request, token & budget limits, agent fan-out & tool limits
Attribution CaptureCapture source metadata from L6; validate user, app, agent & team; stamp use case & initiative

The same response carries the published tooling table, which names gateway and router options such as LiteLLM, Portkey, Cloudflare AI Gateway, Kong AI Gateway, OpenRouter and Vercel AI Gateway.

tokenomics · get_layer {layer: "l5"}

3

List the levers at that layer

3 lever(s):
- **Complexity routing** (`l5-complexity-routing`, stack-primary-lever, L5, t-n-k-a/t-infinity)
- **Budgets** (`l5-budgets`, stack-primary-lever, L5, t-n-k-a/t-infinity)
- **Agent caps** (`l5-agent-caps`, stack-primary-lever, L5, t-n-k-a/t-infinity)

All three bound the amplifying classes, T(n·k·a) and T(∞). As the layer text puts it: “the first is an optimization and the second is a containment: a workload with no ceiling has no worst case.”

Search every source for the evidence

Search ranks sections across all 14 documents. The top hit for “model routing gateway” is the Routing Wars episode's key takeaways:

“An AI bill with no routing policy is a governance gap, not just a cost problem. Start with visibility, then route. Instrument routing early. Log which model served each request and break quality metrics down by model.”

Episode 18 adds the final survey figure, served as document state-of-ai-tokenomics-takeaways: “86% of organizations are running or evaluating model routing.” And the cache explainer's model-switching section warns that a router that switches models mid-session throws away a warm cache, which is the bridge to the AI caching worked example.

The one-minute version

Start with get_tokenomics_info {} to see what is served and how settled each source is. Use the stack and Big-T tools to decide where to act, calculate_cache_metrics to measure caching on your own numbers, and get_crosslinks to hand off to the framework and FOCUS servers. Quote the status line with every answer: most of this guidance is a draft or release candidate.
